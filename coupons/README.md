# موقع أكواد الخصم

موقع مستقل تمامًا عن بقية مشاريع المستودع: صفحات HTML **ثابتة** مبنية للظهور في نتائج قوقل،
بدون قاعدة بيانات وبدون أي حزم خارجية (Node فقط).

> ⚠️ الأكواد الموجودة حاليًا في `data/stores.json` هي **بيانات تجريبية** (`SAMPLE…`).
> استبدلها بأكواد حقيقية قبل ربط الدومين ونشر الموقع للجمهور.

---

## الهوية البصرية والخطوط

الموقع مبني على نهج **ثمانية**: برتقالي دافئ، عناوين بخط مُشبَك (Serif)، متن سانس، ومساحات بيضاء واسعة.

**الألوان** مأخوذة حرفيًا من حزمة نظام تصميم ثمانية الرسمية
([`@thmanyah/design-system`](https://www.npmjs.com/package/@thmanyah/design-system) — رخصة MIT):

| الدور | اللون |
|---|---|
| العلامة | `#FF9500` · `#CC7700` · `#995A00` |
| فاتح العلامة | `#FFF5E6` · `#FFE5BF` |
| المحايد | `#F5F7FA` · `#E4E7EB` · `#616E7C` · `#52606D` · `#3E4C59` |
| دلالي | نجاح `#10B981` · خطأ `#EF4444` · تنبيه `#F59E0B` |

**الخط** يُضبط من `data/site.json` عبر مفتاح `"font"`:

| القيمة | ما يُحمَّل | الترخيص |
|---|---|---|
| `"thmanyah"` | خط ثمانية (Thmanyah Sans + Serif Display) | **شخصي فقط** — اقرأ التنبيه أدناه |
| `"plex"` | IBM Plex Sans Arabic + Noto Naskh Arabic | OFL — تجاري مسموح |

في الوضعين يُحمَّل الخطّان المرخّصان (Plex + Naskh) كاحتياطي، فلو تعذّر خط ثمانية بقي الموقع على هويته
ولم يسقط إلى خط النظام.

> ⚠️ **تنبيه ترخيص مهم:** ترخيص خط ثمانية — بحسب التنبيه المنشور في حزمة الويب نفسها —
> **للاستخدام الشخصي فقط**، ولا يُجيز استضافة ملفات الخط أو إعادة توزيعها من خادمك أو CDN خاص.
> موقع أكواد خصم فيه روابط أفلييت أو دخل = **استخدام تجاري**.
> قبل النشر للجمهور: راسل ثمانية على [Ask@thmanyah.com](mailto:Ask@thmanyah.com) لترخيص موسّع،
> أو بدّل `"font"` إلى `"plex"` — وهما الخطان المنصوص عليهما في نظام تصميم ثمانية الرسمي،
> فالنتيجة قريبة جدًا وبرخصة حرة تمامًا.
>
> الشكل العام مستوحى من ثمانية لا منسوب إليها: الموقع يحمل اسمه وشعاره الخاص،
> ولا يستخدم اسم ثمانية ولا علامتها.

## التشغيل محليًا

```bash
cd coupons
npm run dev      # يبني الموقع ويشغّله على http://localhost:4173
npm run build    # يبني فقط → مجلد dist/
```

لا يحتاج `npm install` — لا توجد أي اعتماديات.

## إضافة متجر أو كود جديد

كل شيء في ملف واحد: `data/stores.json`.

```json
{
  "slug": "noon",                    // يظهر في الرابط: /store/noon/ — إنجليزي وبدون مسافات
  "name": "نون",                     // اسم المتجر كما يظهر للزائر
  "url": "https://www.noon.com/",    // رابط المتجر (أو رابط الأفلييت)
  "logo": "/images/noon.png",        // اختياري — اتركه "" ليُولَّد شعار بحرف الاسم الأول
  "brandColor": "#FEEE00",           // لون الشعار المولَّد
  "category": "تسوق عام",            // يُستخدم في أزرار التصنيف بالصفحة الرئيسية
  "description": "وصف قصير للمتجر.",
  "codes": [
    {
      "code": "BARO10",              // الكود نفسه — هو ما يُنسخ
      "title": "خصم 10% على الطلب الأول",
      "discount": "10%",             // يظهر كوسم ملوّن
      "expires": "2026-12-31",       // يُخفى الكود تلقائيًا بعد هذا التاريخ
      "terms": "بحد أدنى 200 ريال.",
      "featured": true               // اختياري — يبرز الكود ويضع وسم «الأكثر استخدامًا»
    }
  ]
}
```

**ملاحظات:**
- الأكواد المنتهية تُحذف من الموقع تلقائيًا عند كل بناء، ومتجر بلا أكواد فعّالة لا تُنشأ له صفحة.
- الشعارات: شغّل `npm run logos` ليجلبها تلقائيًا، أو ضعها يدويًا في `public/images/`
  وأشِر إليها بـ `/images/اسم-الملف.png`. الحجم المناسب ٢٠٠×٢٠٠ بكسل.
- بعد أي تعديل: اعمل commit و push — Vercel يعيد البناء والنشر تلقائيًا.

## شعارات المتاجر

```bash
npm run logos            # يجلب شعار كل متجر ليس له شعار محلي
npm run logos -- --force # يعيد جلب الجميع
npm run logos -- noon    # متجر بعينه
```

الأداة تقرأ `data/stores.json`، وتستخرج الشعار لكل متجر بالترتيب التالي:

1. وسوم `<link rel="apple-touch-icon">` و `icon` في صفحة المتجر نفسها — الأكبر أولًا
2. `‎/apple-touch-icon.png` و `‎/favicon.ico` مباشرةً
3. خدمة أيقونات DuckDuckGo
4. خدمة أيقونات قوقل بمقاس ٢٥٦

ثم تحفظ الملف في `public/images/<slug>.png` وتكتب مساره في `stores.json`. ما يقل حجمه عن
٦٠٠ بايت يُتجاهل — فذلك غالبًا أيقونة شفافة أو صفحة خطأ، لا شعار.

**لماذا سكربت منفصل لا خطوة في البناء؟** لأن الشعارات لا تتغيّر، ولأن البناء يجب أن يبقى
بلا اتصال بالشبكة: بناءٌ يعتمد على مواقع خارجية يفشل يوم تتعطّل هي، لا يوم تتعطّل أنت.

الشعارات تُحفظ في المستودع وتُرفع مع الكود، فلا يوجد طلب لطرفٍ ثالث عند تصفّح الزائر —
أسرع، وأفضل لخصوصيته.

**بديل تلقائي:** المتجر بلا شعار يُعرض بأول حرف من اسمه على تدرّجٍ من `brandColor`.
فلا تظهر مساحة فارغة أبدًا، وتستطيع ترك الشعار فارغًا عمدًا.

**ملاحظة:** الشعارات تُعرض بلاطةً بيضاء دائمًا حتى في الوضع الداكن، لأن أغلبها داكن على
خلفية شفافة فيختفي لو وُضع على سطحٍ داكن.

## المساحات الإعلانية

الإعلانات تُدار من `data/ads.json`. الملف فارغ الآن، وكل موضعٍ بلا معلن يعرض **مساحة حجز**
تدعو المعلنين إلى صفحة `/advertise/` بدل أن يترك فراغًا في التصميم.

### إضافة معلن

انسخ بنية `data/ads.example.json` إلى `data/ads.json`:

```json
{
  "id": "acme-q4",
  "slot": "hero",                       // hero | feed | store | blog
  "advertiser": "اسم الشركة",
  "title": "عنوان الإعلان",             // نصٌّ بديل للصورة، ومهم للوصولية
  "url": "https://example.com/landing",

  // إعلان بصورة مصمَّمة — الصورة هي الإعلان كلّه
  "banner": "/images/acme-1800x300.jpg",
  "bannerMobile": "/images/acme-800x400.jpg",

  // أو إعلان نصّي بدل الصورة
  "body": "سطر أو سطران.",
  "cta": "اعرف أكثر",
  "image": "/images/acme-logo.png",      // شعار ٢٠٠×٢٠٠
  "brandColor": "#0B5FFF",

  "starts": "2026-10-01",                // يظهر تلقائيًا في هذا اليوم
  "ends": "2026-10-31",                  // ويختفي تلقائيًا بعده
  "priority": 1,
  "targetCategory": "إلكترونيات"         // اختياري — يحصر الظهور في تصنيف واحد
}
```

وجود `banner` يجعل الإعلان صورةً كاملة؛ غيابه يجعله نصيًّا بالشعار والعنوان والزر.

### مقاسات الصور

الإعلان نوعان: **بصورة مصمَّمة** (المعلن يملك التصميم كاملًا) أو **نصّي** (شعار + عنوان + زر).

| المفتاح | المقاس | النسبة | يظهر في |
|---|---|---|---|
| `banner` | **١٨٠٠ × ٣٠٠** | ٦:١ | الشاشات فوق ٦٠٠ بكسل |
| `bannerMobile` | **٨٠٠ × ٤٠٠** | ٢:١ | الجوال (أقل من ٦٠٠ بكسل) |
| `image` | **٢٠٠ × ٢٠٠** | ١:١ | شعار الإعلان النصّي |

**لماذا نسختان؟** المساحة العلوية تُعرض ١١٢٤×١٨٧ على سطح المكتب و٣٧٨×١٨٩ على الجوال — نسبتان
مختلفتان تمامًا. صورة واحدة تُقصّ حتمًا في إحداهما، ومع `bannerMobile` يبقى تصميم المعلن سليمًا
في الاثنتين. إن لم تُرسل نسخة الجوال، تُستخدم العريضة مقصوصةً من الجانبين.

**عند التصميم:** ضع العناصر المهمّة — الشعار والعنوان وزر الإجراء — في **الوسط الأفقي** بعيدًا
عن الحواف بمقدار ٨٪ على الأقل، حتى لا يُقصّ شيء على المقاسات المتوسطة. الصيغة `jpg` للتصاميم
ذات التدرّجات و `png` لما فيه شفافية. احرص أن يقل حجم الملف عن ٢٠٠ ك.ب.

**المقاسات المعروضة فعليًا** (قِسناها في المتصفح):

| الموضع | سطح المكتب | لوحي | جوال |
|---|---|---|---|
| علوي (`hero`) | ١١٢٤ × ١٨٧ | ٧٣٢ × ١٢٢ | ٣٧٨ × ١٨٩ |
| بطاقة القائمة (`feed`) | ٣٢٩ × ٢٢٦ | ٢٣٣ × ٢٣٧ | ١٨٢ × ٢٣٣ |
| صفحة متجر (`store`) | ١١٢٤ × ١٢٢ | — | — |
| داخل مقال (`blog`) | ٧٨٤ × ٩٩ | — | — |

### المواضع

| `slot` | أين يظهر |
|---|---|
| `hero` | أسفل شرائح التصنيف في الصفحة الرئيسية |
| `feed` | بطاقة بين بطاقات الأكواد — بعد الرابعة ثم كل ثماني بطاقات |
| `store` | صفحات المتاجر وصفحات التصنيفات |
| `blog` | صفحة المدونة، وداخل كل مقال بعد ثلث المحتوى |

**ملاحظتان تقنيّتان مهمّتان:**

1. كل إعلان يحمل وسم «إعلان» ظاهرًا، ورابطه `rel="nofollow sponsored"`. هذا شرط قوقل
   للمحتوى المدفوع — وتجاهله يعرّض فهرسة الموقع كلّه للعقوبة، لا الإعلان وحده.
2. مدّة الحملة تُضبط بـ `starts` و `ends`، ويسري ذلك عند كل بناء. أي أن انتهاء الحملة
   لا يحتاج تدخّلًا يدويًا، لكنه يحتاج إعادة نشر (أي commit) ليأخذ مفعوله.

## المدونة

المقالات في `data/posts.json`، وتُبنى في `/blog/` و `/blog/<slug>/`.

### الربط المباشر بالأكواد

أهم ما في المدونة أنها **ليست نصًّا جامدًا**: كتلة `codes` داخل المقال تقرأ من
`data/stores.json` لحظة البناء. يعني أن تعديلك لكود في الأعلى يظهر داخل المقال تلقائيًا
دون أن تلمس نص المقال.

```json
{ "type": "codes", "store": "noon", "title": "أكواد نون الفعّالة الآن" }
{ "type": "codes", "category": "أزياء", "limit": 6 }
{ "type": "codes", "scope": "featured", "title": "الأفضل الآن" }
```

والربط في الاتجاه المعاكس أيضًا: إذا حمل المقال حقل `"store": "noon"` ظهر وسم **دليل**
على بطاقة نون في كل مكان، وظهر رابط الدليل داخل صفحة المتجر.

### كتل المقال المتاحة

| النوع | الاستخدام |
|---|---|
| `p` | فقرة — يقبل وسوم HTML بسيطة مثل `<strong>` |
| `h2` / `h3` | عنوان — يُولَّد له معرّف ويدخل فهرس المحتويات تلقائيًا |
| `list` | قائمة (`"ordered": true` لترقيمها) |
| `callout` | صندوق تنبيه بارز |
| `table` | جدول — `head` و `rows` |
| `faq` | أسئلة وأجوبة — تُولَّد لها بيانات `FAQPage` المنظّمة |
| `codes` | **أكواد حيّة** من بيانات المتاجر |

فهرس المحتويات يظهر تلقائيًا حين يتجاوز المقال ثلاثة عناوين `h2`.

## واجهة التطبيق (PWA)

الموقع يعمل كتطبيق مستقل عند إضافته للشاشة الرئيسية:

- شريط تبويبات سفلي على الجوال (الأكواد · المتاجر · المدونة · بحث · المفضلة)
- `manifest.webmanifest` بأيقونات ٤ مقاسات وأيقونة maskable
- عامل خدمة (`sw.js`) يجعل الصفحات المزارة تعمل بلا إنترنت، ونسخته مشتقّة من محتوى
  الأكواد والمقالات — فكل نشرٍ فيه جديد يُبطل المخزَّن القديم تلقائيًا
- زر «ثبّت التطبيق» يظهر في المتصفحات التي تدعمه
- المفضلة وسجل النسخ محفوظان في `localStorage` على جهاز الزائر — لا خادم ولا حساب

| العنصر | الحالة |
|---|---|
| صفحة مستقلة لكل متجر وتصنيف ومقال | ✅ |
| الأكواد ظاهرة نصًّا في HTML قبل أي جافاسكربت | ✅ |
| `Offer` منظّم لكل كود مع رابطه المباشر | ✅ |

| روابط داخلية: كود ← متجر ← تصنيف ← دليل | ✅ |
| روابط المتاجر `rel="nofollow sponsored"` | ✅ |

## الدومين والظهور في قوقل

1. اشترِ الدومين واربطه بمشروع Vercel.
2. حدّث `"domain"` في `data/site.json` بالدومين الجديد — منه تُبنى روابط `canonical` و `sitemap.xml`.
3. أضف الموقع في [Google Search Console](https://search.google.com/search-console) وأرسل `https://دومينك/sitemap.xml`.

**ما هو مُهيّأ مسبقًا:** صفحة مستقلة لكل متجر، `title` و `description` لكل صفحة،
روابط `canonical`، `sitemap.xml` و `robots.txt`، بيانات منظمة (`Offer` و `FAQPage` و `BreadcrumbList`)،
صور المشاركة (`og.png`)، دعم RTL كامل، وسرعة تحميل عالية لأن الصفحات ثابتة.

روابط المتاجر الخارجية تحمل `rel="nofollow sponsored"` — وهو المطلوب من قوقل لروابط الأفلييت.

## البنية

```
coupons/
├── data/
│   ├── site.json           ← اسم الموقع والدومين والخط
│   ├── stores.json         ← المتاجر والأكواد (تعدّله يوميًا)
│   ├── posts.json          ← مقالات المدونة
│   ├── ads.json            ← الإعلانات المدفوعة
│   └── ads.example.json    ← نموذج مرجعي، لا يُقرأ في البناء

├── build.js                ← مولّد الصفحات الثابتة
```
