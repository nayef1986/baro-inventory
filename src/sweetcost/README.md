# SWEET COST

نظام حساب تكلفة تصنيع أطباق الحلى، الهدر، الربح، وهامش الربح.

يعمل كتطبيق مستقل داخل هذا المستودع على المسار `/sweet-cost.html`.
تطبيق باروو الحالي على `/` لم يتغيّر.

## التشغيل

1. شغّل `supabase/migrations/0001_sweet_cost.sql` في محرّر SQL داخل مشروع Supabase.
2. انسخ `.env.example` إلى `.env.local` وضع رابط المشروع ومفتاح anon.
3. `npm install && npm run dev` ثم افتح `/sweet-cost.html`.

## الأوامر

| الأمر | ماذا يفعل |
| --- | --- |
| `npm test` | اختبارات محرك التكلفة (19 اختباراً) |
| `npm run typecheck` | فحص الأنواع — TypeScript strict |

## قواعد ثابتة في هذا الكود

- **لا تكلفة مُدخلة يدوياً.** كل رقم تكلفة يُشتق من آخر سعر شراء مسجّل.
- **معادلات التكلفة في `cost.ts` فقط.** لا تُكرَّر في SQL ولا في شاشة.
- **الأسعار القديمة لا تُحذف.** كل شراء يضيف سجلاً جديداً في `sc_ingredient_prices`.
- **لقطات التكلفة تُحفظ مع الإنتاج والهدر**، فلا تتغيّر أرقام الماضي عند تغيّر الأسعار.
- **المبالغ `numeric` في قاعدة البيانات**، وليست `float`.
- **كل رسالة من المساعد مبنية على رقم موجود فعلاً.** لا تحفيز عشوائي ولا توقعات.

## منطق الهدر

```
سعر الوحدة      = سعر العبوة ÷ حجم العبوة
التكلفة الفعلية = سعر الوحدة ÷ (1 − نسبة الهدر)
تكلفة المكون    = التكلفة الفعلية × الكمية
```

نسبة الهدر تعني أن جزءاً من العبوة يضيع قبل أن يصل للطبق. القسمة على
`(1 − الهدر)` ترفع تكلفة الوحدة الصالحة: اشتريت 100% ودفعت ثمنها كاملاً،
بينما استفدت من 80% فقط.

تقييم **الهدر المسجّل** يستخدم سعر الشراء الخام بلا هذا التضخيم، لأن ما ضاع
هو ما دُفع ثمنه فعلاً.

## من أين تأتي المبيعات

النظام إنتاج بالجملة بسعر بيع ثابت، فلا توجد فواتير بيع. كل دفعة إنتاج
تحمل `produced_units` و `sold_units`، والمبيعات = `sold_units × sell_price`
وقت الإنتاج.
