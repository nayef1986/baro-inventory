# SWEET COST

نظام حساب تكلفة تصنيع أطباق الحلى، الهدر، الربح، وهامش الربح.

يعمل كتطبيق مستقل داخل هذا المستودع على المسار `/sweet-cost.html`.
تطبيق باروو الحالي على `/` لم يتغيّر.

## التشغيل

1. شغّل `supabase/migrations/0001_sweet_cost.sql` في محرّر SQL داخل مشروع Supabase.
2. انسخ `.env.example` إلى `.env.local` وضع رابط المشروع ومفتاح anon.
3. `npm install && npm run dev` ثم افتح `/sweet-cost.html`.

## الأوامر

| الأمر | ماذا يفعل |
| --- | --- |
| `npm test` | اختبارات محرك التكلفة (19 اختباراً) |
| `npm run typecheck` | فحص الأنواع — TypeScript strict |
| `npm run lint` | ESLint على `src/sweetcost` فقط |
| `npm run build` | بناء التطبيقين معاً |

## البنية

```
src/sweetcost/
  lib/cost.ts        محرك التكلفة — المصدر الوحيد لأي حساب تكلفة
  lib/cost.test.ts   اختبارات المحرك
  lib/units.ts       الوحدات والتحويل بينها
  lib/derive.ts      اشتقاق تكلفة المكونات والوصفات من البيانات
  lib/analytics.ts   تجميع الأرقام على فترة زمنية
  lib/coach.ts       المساعد الذكي — رسائل مبنية على أرقام حقيقية
  lib/api.ts         قراءة وكتابة Supabase
  components/InvoicePrint.tsx  قالب فاتورة التوريد للطباعة/PDF
  screens/           الشاشات السبع
```

## قواعد ثابتة في هذا الكود

- **لا تكلفة مُدخلة يدوياً.** كل رقم تكلفة يُشتق من آخر سعر شراء مسجّل.
- **معادلات التكلفة في `cost.ts` فقط.** لا تُكرَّر في SQL ولا في شاشة.
- **الأسعار القديمة لا تُحذف.** كل شراء يضيف سجلاً جديداً في `sc_ingredient_prices`.
- **لقطات التكلفة تُحفظ مع الإنتاج والهدر**، فلا تتغيّر أرقام الماضي عند تغيّر الأسعار.
- **المبالغ `numeric` في قاعدة البيانات**، وليست `float`.
- **كل رسالة من المساعد مبنية على رقم موجود فعلاً.** لا تحفيز عشوائي ولا توقعات.

## منطق الهدر

```
سعر الوحدة      = سعر العبوة ÷ حجم العبوة
التكلفة الفعلية = سعر الوحدة ÷ (1 − نسبة الهدر)
تكلفة المكون    = التكلفة الفعلية × الكمية
```

نسبة الهدر تعني أن جزءاً من العبوة يضيع قبل أن يصل للطبق. القسمة على
`(1 − الهدر)` ترفع تكلفة الوحدة الصالحة: اشتريت 100% ودفعت ثمنها كاملاً،
بينما استفدت من 80% فقط.

تقييم **الهدر المسجّل** يستخدم سعر الشراء الخام بلا هذا التضخيم، لأن ما ضاع
هو ما دُفع ثمنه فعلاً.

## من أين تأتي المبيعات

**فواتير التوريد هي مصدر المبيعات.** كل فاتورة صادرة أو مدفوعة تدخل في
حساب المبيعات والربح؛ المسودات والملغاة لا تدخل.

`sold_units` في شاشة الإنتاج يبقى لمعرفة ما خرج من المطبخ، ولا يُحتسب
إيراداً — وإلا حُسبت المبيعات مرتين.

| الرقم | من أين |
| --- | --- |
| المبيعات | مجموع الفواتير بدون الضريبة |
| تكلفة المبيعات | لقطة تكلفة الوحدة في بنود الفاتورة |
| تكلفة الإنتاج | الدفعات المنتجة في الفترة — للعلم، خارج معادلة الربح |
| الربح | المبيعات − (تكلفة المبيعات + الهدر) |

الضريبة المحصّلة تُعرض ولا تدخل الربح، لأنها ليست إيرادك.

## الفواتير و PDF

التصدير يتم بطباعة المتصفح («حفظ كـPDF») لا بمكتبة PDF: المتصفح يرسم
العربية وتشكيلها واتجاهها بشكل صحيح، بلا أي اعتماد خارجي. القالب في
`components/InvoicePrint.tsx` ويُعرض عبر portal إلى `body`، ويظهر في
الطباعة فقط عبر `@media print` في `styles.css`.

كل بند يحفظ **لقطة** من اسم المنتج ووحدته وسعره وتكلفته وقت الإصدار،
فتغيّر الأسعار أو حذف وصفة لاحقاً لا يغيّر فاتورة صدرت.

الضريبة اختيارية من «بيانات المتجر». هذه **فاتورة تجارية**، وليست فاتورة
ضريبية إلكترونية معتمدة من هيئة الزكاة والضريبة والجمارك — تلك تتطلب رمز
QR ومتطلبات فوترة إضافية.## الهوية

أخضر زيتوني دافئ وبيج. الرموز كلها في `styles.css` تحت `@theme` — غيّر
الرمز يتغيّر التطبيق كله.

| | |
| --- | --- |
| `#26381F` | التنقل والبطاقات الداكنة |
| `#55793F` | الأفعال وأشرطة التقدم |
| `#F4EEE1` | الأرضية |
| `#EAE1CE` | الفواصل والحقول |
| `#8A6218` | الإنجازات |
| `#A4442E` | التنبيهات |

الخط: **القاهرة** من Google Fonts — 400 للنص، 600 للتأكيد، 900 للعناوين.
